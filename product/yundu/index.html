走 WARP 的三个硬优势

不是“翻墙器”，是把出站出口收敛到 Cloudflare 边缘的正向代理用法。

01

走 WARP，更安全

设备到 Cloudflare 边缘之间由 WARP 客户端建立加密隧道（WireGuard 内核），公网 Wi-Fi / 校园网下避免明文裸奔；边缘侧再按目标站 HTTPS 走标准 TLS。

02

支持 HTTP/3 / QUIC

WARP 边缘与客户端之间支持 QUIC 传输，弱网、高丢包、移动网络下握手更快；对已启用 HTTP/3 的目标站可端到端享受 0-RTT 优势。

03

204 测速自检

内置探测端点 https://speedtest-http.gybc.top/204，一键看隧道是否通、Anycast 节点延迟多少，不下载大文件、不耗流量。

链路怎么走

你的机器 → 系统代理 → CF Warp → 公网。和 frp 正好反过来：frp 管“别人进来”，百川云渡管“你出去”。

① 应用设代理浏览器 / CLI 指向 127.0.0.1:10808（SOCKS5）或 HTTPS 代理端口
② WARP 客户端本机 warp-cli 把流量封进 WARP 隧道，仅代理态生效
③ Anycast 边缘BGP 就近落到 Cloudflare 边缘节点，QUIC/WireGuard 加密
④ 出公网边缘代你访问目标站，响应原路回本机应用

和 frp 是什么关系

frp（反向 / 入站）

内网服务端口 → 公网 VPS → 外部访客。解决“没公网 IP 怎么让人访问我”。

百川云渡（正向 / 出站）

本机应用 → WARP 边缘 → 目标公网。解决“我的出口怎么更稳更近更加密”。

共同点

都是客户端主动外连、不依赖入站端口、不碰系统路由表，属于合法网络工具范畴。
